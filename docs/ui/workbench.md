# CoSeed 工作台界面设计

状态：第一版界面草案，供 review；本文中的管理入口尚未实现。既有阅读原型继续作为视觉和内容展示依据。

## 整体布局

视觉遵循[全局设计系统](design-system.md)：系统字体、松针绿、白色主体和轻手绘标记，支持明暗模式。左侧负责项目选择和内容导航，中间负责主要内容，右侧负责当前内容的阅读目录。项目选择、需求记录与回顾入口是本版新增建议，不重新设计已有综述和设计图的内容规范。

```text
┌──────────────────┬────────────────────────────────────┬─────────────────┐
│ CoSeed           │                                    │ 阅读目录        │
│                  │ 当前页面                           │                 │
│ 项目：CoSeed  ▾  │                                    │ 产品是什么      │
│                  │ 项目综述                           │ 核心概念        │
│ 项目综述         │                                    │ 使用示例        │
│ 需求推进         │ 01 产品是什么                      │   示例小节……    │
│ 业务设计         │ 02 核心概念：关系图、释义列表       │                 │
│                  │ 03 使用示例：小节图、例子正文       │                 │
│                  │                                    │                 │
│                  │                         查看需求演变 │                 │
│                  │                                    │                 │
│ 项目设置         │                                    │                 │
│ 回顾             │                                    │                 │
└──────────────────┴────────────────────────────────────┴─────────────────┘
```

右侧只放当前页面需要的目录。业务设计以图为主时不为凑齐三栏放一份重复说明；需求列表页也可以使用完整的中间区域。窄屏继续沿用当前阅读目录的折叠方式。

## 项目选择

左侧顶部显示当前项目。展开后可以选择已建立的项目，或进入“新建项目”。

新建项目首先只填写项目名称，业务仓库地址可选，不要求登记用户电脑的仓库目录。创建后进入该项目的综述；内容为空时说明需要先整理项目内容，不伪造已完成的需求、设计或回顾记录。项目设置用于查看和调整项目资料，仓库目录的变更规则需随项目识别方案确认。

项目切换会改变综述、需求和设计的共同归属，不允许正文显示一个项目而写入另一个项目。

## 项目综述

保留“产品是什么、核心概念、使用示例”及其已认可的阅读方式。右侧目录负责定位章节。

每节在需要时提供一个轻量的“需求演变”入口，进入与该节有关的需求和推进记录。它不是额外复制一份历史，也不在正文中到处插入管理卡片。

从推进记录中的“查看当前内容”可以返回对应综述段落或设计对象，形成双向关联。

## 需求推进

先展示需求列表，每行是一项可独立讨论和验收的目标，而不是一条聊天或一次回顾。

```text
需求推进

理解项目的核心概念          3 条记录   查看当前内容
快速定位长篇综述            2 条记录   查看当前内容
```

第一版不在页面上预设尚未确定的需求状态。选择需求后进入详情页。

```text
需求推进 / 理解项目的核心概念

让读者理解项目中的关键业务名词和关系……
[查看相关综述]  [查看相关设计]

推进记录
│
├─ 明确核心概念的内容边界
│  一段自由 Markdown，说明本次明确了什么……
│  来源                                     编辑
│
├─ 确定关系图和词条的展示方式
│  一段自由 Markdown，说明决定及其影响……
│  来源                                     编辑
│
└─ 完成原型并验证定位
   一段自由 Markdown，说明实际完成及验证结果……
   来源                                     编辑
```

详情上方说明当前需求，下面展开它的推进记录。编辑旧记录时提供保存和取消，保存后可查看修订历史；后来发生的新变化追加记录。

综述、概念、需求和设计等内容同样提供“更正历史”入口。历史中逐条展示修改前后、执行者、修改时间和具体来源；从来源可阅读支撑更正的原始片段或定位相应材料。Agent 回顾更正的依据不能只显示成一个执行器名称标签，人工直接编辑则明确标识该次编辑。发生时间无法核实时保留未知，不拿最后保存时间冒充发生时间。

列表中的记录数应由实际记录得到。本文数字来自业务示例，不作为正式项目已经存在这些数据的声明。

## 业务设计

保留业务全景和模块内部图，进入模块时沿用清晰的边界、节点及关系。关键技术方案仍依附相关节点或范围。

被需求影响的模块或设计对象，可关联到对应需求记录；查看记录后也能回到当前设计。阅读图时不在外围重复列出图中已经表达的全部关系。

## Agent 接入

左侧底部的“Agent 接入”进入 `#/agent-guide`。正式前端已展示[简版指南](../operations/agent-integration.md)：连接 CoSeed、开始一个项目、推进一轮工作、保存并查看结果。它先固定阅读顺序，后续按提示词标准细化内容。

桌面采用左侧导航、中间正文、右侧四节目录。标题旁提供“复制说明”，复制权威 Markdown 全文；窄屏把目录收进顶栏。点击目录和直接打开章节链接均定位正文，滚动更新高亮。沿用全局字体、间距、松针绿和明暗模式；不重复创建一套样式 Token。

正文标明内容草稿及业务读写工具未接入，不用连接状态替代业务能力验证。文档源内容直接进入构建，不在 React 中另存一份正文。

## 回顾入口

左下方提供统一的“回顾”入口。首版流程沿用已经确定的协作方式：用户向所用 Coding Agent 明确发起回顾，由 Agent 通过 MCP 整理并更新 CoSeed；页面承接阅读结果及追溯来源。

入口展示如何发起回顾，以及当前项目已有的回顾结果。MCP 和对话来源尚未接入时，必须明确说明尚未执行，不能用按钮点击伪造一次已完成回顾。

接入后，一次回顾结果按“更新了哪些需求、修正了哪些当前内容、还有哪些材料缺口”呈现，点击具体结果回到原内容。回顾是一次整理工作，不增加一个与业务内容无关的大型仪表盘。

CoSeed 不管理 Agent 执行器，本版不设计由页面直接调度某个 Coding Agent 的能力。

## 本版界面需要共同确认的部分

- 左侧新增“需求推进”入口，同时通过双向内容链接保持它与项目综述、设计的联系。
- “需求演变”的确切位置和视觉权重，结合实际综述长度再验证。
- 项目设置中仓库识别及路径变更行为，需要与业务设计的待定问题一起确认。
- 新增管理界面的交互和数据持久化尚未实现；既有原型已经验证的阅读行为不因此自动视为管理能力完成。
