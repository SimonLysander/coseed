# CoSeed 全局设计系统 v1

状态：已确认的全局设计系统 v1。系统字体、阅读排版和松针绿已接入正式前端与独立样板；正式工作台已接入项目入口和综述阅读，需求推进与业务设计页面已接入。

所有层级的前端组件、页面和图形都遵循本规范。唯一数值来源位于应用代码：[基础 Token](../../src/web/design-system/tokens.json) 管理字体、排版、尺寸、形态和动效，[主题色板](../../src/web/design-system/themes.json) 管理明暗语义色和固定的松针绿。文档解释用法，不另建一份手工维护的数值源。

运行时由 [DesignSystemProvider](../../src/web/design-system/DesignSystemProvider.tsx) 统一设置 CSS 变量、Ant Design 和 Motion；正式前端、普通样板和精修阅读页都使用它。样板不再维护独立的配色、字体候选或主题解析器。

## 1. 核心思路和取舍

一份正在被阅读、标注和推敲的项目工作笔记，保留人的笔触，承载严谨的内容。

- **结构有秩序**：清楚的网格、对齐和阅读顺序，默认紧凑，关键内容直接可见。
- **表达有笔触**：手写注释、圈选、箭头和局部下划线体现人的书写与推敲；标记指向具体内容，正文和代码保持端正清晰。
- **强调有语义**：淡彩、圈选、下划线标明重点、范围或关系；同一语境使用稳定的语义映射。
- **交互有反馈**：动效回应操作和真实状态变化，控件和图形位置稳定。

发生冲突时，优先顺序为：表达正确和可读性 → 操作稳定和响应流畅 → 风格和动效。

本版采用偏紧凑的工作台密度。通过收紧外层留白、区块间距和控件尺寸提高信息密度，不通过缩小关键文字、降低对比度或省略图中信息实现紧凑。

## 2. 明暗模式和配色

### 两种显示偏好

| 偏好 | 行为                                     |
| ---- | ---------------------------------------- |
| 浅色 | 固定使用净白模式，系统变化不覆盖手动选择 |
| 深色 | 固定使用炭黑模式，系统变化不覆盖手动选择 |

主题色固定为松针绿，显示模式和手绘风格分别管理。切换明暗不清空输入草稿、当前阅读位置或浮层状态。布局、字号、轮廓和节点语义保持一致，模式切换只更新语义色及必要的阴影。

显示偏好属于用户级界面设置，跨项目一致。正式应用使用 `coseed:appearance`，设计样板使用 `coseed-design-preview:appearance`，均保存在浏览器本地，不写入项目内容或服务配置。两个入口共用实现、分别保存偏好；旧样板记录中的浅色、深色继续有效，旧跟随系统设置回到默认浅色，旧强调色不再恢复。跨浏览器同步未实现。

首次使用默认浅色，之后首帧从保存偏好初始化背景与文字，避免深色偏好先显示白底再翻黑。切换模式直接更新 Token，不对整页播放渐变或位移动画，不重算图形布局。Ant Design 同时使用对应的明暗算法及显式语义色，控件、浮层、代码、图节点和关系标签一起适配。正式工作台不设顶栏，全局入口置于左侧栏底部；主题入口采用无 Tooltip 的 Ant Design 图标按钮，太阳／月亮使用 AnimateIcons，点击直接切换浅色和深色；不提供菜单或跟随系统模式。正式工作台和样板共用 `AppearanceToggle`，旧的 system 偏好回到默认浅色。

### 固定主题色

主色用于主操作、当前选择、链接和局部笔触，基础背景保持中性。深色强调色同时配套调整按钮文字、聚焦和链接。按钮使用对应模式的 onAccent，不能假定总是白字。

### 状态和图形

成功、提醒、错误、信息提示分别保留绿、赭黄、砖红、蓝灰的语义。深色模式使用深色底与相应浅色前景。状态必须同时有文字或符号，禁用状态用独立前景和背景，不对整个控件随意降低透明度。

| -------------------------- | ------- | ------- |
| 处理组件                   | #EFF5FD | #252F3D |
| 数据对象                   | #EFF8F1 | #26332B |
| 存储（实际存在该类节点时） | #FFF8E8 | #373020 |
| 外部对象或系统             | #F2F2F4 | #2D2D33 |

图形类型还通过内容结构、形状或所属边界区分，不重新引入占位置的类型标签。只按实际模型呈现节点，不为展示配色创造节点类型。连线、端点、文字底衬、代码注释和技术说明都随模式更新，避免深色画布里残留白块或不可读文字。

## 3. 字体和阅读排版

中文界面、正文、标题和旁注统一使用系统无衬线；macOS 通常为苹方，其他平台使用 Token 中的回退栈。不分发系统字体文件。英文字标保留 Patrick Hand Latin 本地字体，附 OFL；数据、字段和路径使用系统等宽字体，关闭编程连字。

| 场景             | 字号 / 行高           | 字重              |
| ---------------- | --------------------- | ----------------- |
| 英文字标         | 28 / 36               | 400               |
| 页面标题         | 26 / 36；手机 24 / 34 | 600               |
| 小节标题         | 17 / 26               | 600               |
| 阅读正文         | 15 / 28               | 400               |
| 界面、按钮、表单 | 14 / 22               | 400；必要标签 500 |
| 导航             | 13 / 22               | 400；当前项 500   |
| 节点名称 / 说明  | 14 / 22；13 / 20      | 600 / 400         |
| 连线说明         | 13 / 18               | 400               |
| 辅助信息         | 12 / 18–20            | 400               |
| TS 字段与代码    | 12 / 20               | 400               |
| 中文旁注         | 18 / 28               | 400               |

正文最大宽度 660px，目录宽 144px，列间距 48px；段间距 12px，小节段前 32px。导航和工具区保持紧凑，正文通过行长、层级和段落间距组织阅读。中文不机械增加字距，普通说明不加粗、不用彩色强调整段。手绘痕迹集中在少量圈选、下划线和注释中。

这一分层取向参考 [Carbon 的产品排版体系](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview)，具体数值是本项目已确认的设计取值。

`/?view=reading` 保留已确认的只读阅读样例，只切换明暗模式。MiSans、Noto 和中文手写字体的试用文件及比较器已经移除，避免将固定样例子集误用于动态业务内容。唯一额外字体资源为约 24 KB 的完整 Latin 字标字体，正式包同时携带许可。

## 4. 间距和布局

采用 4px 基础刻度，并保留 2px 的细节调整：常用间距为 4、8、12、16、20、24、32、40、48px，6px 只作小范围对齐。

| 项目                           | 本版取值             |
| ------------------------------ | -------------------- |
| 样板工具栏（正式工作台无顶栏） | 48px                 |
| 完整侧栏 / 图标栏              | 208px / 56px         |
| 侧栏内边距                     | 12px                 |
| 导航行高 / 行间距              | 36px / 4px           |
| 页面内边距                     | 32px；窄屏 20px      |
| 正文最大宽度                   | 660px                |
| 阅读目录宽度 / 列间距          | 144px / 48px         |
| 小节间距                       | 32px                 |
| 面板内边距                     | 16px                 |
| 表单字段间距                   | 12px                 |
| 常规控件 / 小控件 / 大控件     | 32px / 28px / 40px   |
| 列表最小行高                   | 36px，允许随内容增高 |
| 触控目标                       | 至少 44px            |

常规按钮左右留白 12px，图标与文字间距 6px；图标按钮保持方形点击区域。小控件适用于辅助工具栏，不作为所有主操作的默认尺寸。触控环境扩展实际可点击区域，不能让相邻目标重叠。

### 响应式

- **1280px 起**：完整侧栏；阅读页可显示右侧目录。图形页使用余下画布，不强行加入阅读目录。
- **1024–1279px**：完整侧栏，目录收进明确的目录入口。
- **768–1023px**：侧栏切换为 56px 图标栏；目录收起，内容保持 20px 留白。
- **小于 768px**：独立的 44px 导航按钮打开左侧抽屉，抽屉宽 256px 且不超过视口减去 32px；正文自然单列。

布局按可用容器宽度适配，浏览器放大文字后也必须能阅读和操作。不能只通过整页 transform 缩小来适配窄屏。

### 阅读页的对齐和间距

- 标题区按 12px 间距垂直排列；小节段前 32px，小节内的标题、段落、概念列表和旁注间距均为 12px，底部说明与正文相隔 40px。使用容器 gap 组织内容，避免子元素 margin 叠加。
- 标题、小节标题、正文和底部说明共享正文左边界。桌面核心概念采用 72px 名称列、20px 列间距，名称和解释对齐首行文字基线；旁注对齐解释列。手机改为上下排列，名称与解释间隔 4px，旁注回到正文左边界。
- 右侧目录与文档顶部对齐；目录收起时，在文章标题旁保留明确的“目录”入口。目录链接至少 32px 高，触屏至少 44px 高。锚点跳转保留正文留白。
- 侧栏和目录在短窗口中各自允许纵向滚动，不压缩导航行，也不让底部链接越出可访问区域。手机导航抽屉不超过视口宽度减去 32px。
- 阅读内容允许中文、长标题和连续英文标识换行；强调笔触随文字逐行绘制，不能通过禁止换行撑破内容列。

阅读布局回归覆盖 320–1920px 的断点前后、240px 高的短窗口、长标题和长标识、手机触屏目录及抽屉；见 `tests/design/reading-layout.spec.ts` 和 `tests/design/reading.spec.ts`。

空状态采用正常内容流，区块上下留白 32px，插画最多 144px 宽；不为了填满视口制造巨大的中心留白。说明后紧接真实可执行的下一步，尚未实现的功能明确说明。

## 5. 形态

- 采用柔和、规整的圆角矩形：按钮、输入和导航 10px，面板及弹窗 16px，代码标记等小元素 6px；全部取自形态 Token，Ant Design 共享同一映射。手绘感保留在图标、插画和笔触中。
- 需要边界的容器单层线宽 1px，图形手绘轮廓 1.2px，选中轮廓 1.6px；键盘聚焦使用独立 2px 轮廓和 2px 间隔。
- 手绘轮廓相对标准边界最多偏离 0.8px，使用固定预设或稳定 ID 产生的固定笔触。每次渲染、Hover 和缩放不重新随机生成。
- 点击区域、文字、连接端点和算法边界保持规则；不规则效果位于独立绘制层，不扰动布局或命中判断。
- 普通阅读、组件示例和动效示例默认无外框、无填充块，通过小标题、对齐和留白组织；输入框、可操作控件、图节点、浮层保留其必要边界。只有确有分组或遮挡语义时才增加边界，不叠加重复轮廓或偏移阴影。浮层保留轻量柔和阴影。
- 分隔线可以精确而轻，手绘线也可以连续。虚线保留给有含义的边界或关系，不作为所有组件的统一装饰。
- 淡彩下划线或标记只强调当前选择和少量重点。胶带、图钉、咖啡渍、满屏笔记横线不进入默认组件。

内容采用平涂；本版不使用渐变、玻璃模糊或厚重投影。手绘感来自轮廓、标注和少量插画，不来自文字抖动或整块布局倾斜。

## 6. 组件状态

| 对象         | 默认                     | Hover                  | 选中、按下或聚焦                           |
| ------------ | ------------------------ | ---------------------- | ------------------------------------------ |
| 主按钮       | 强调底、对比文字、细轮廓 | 底色加深；图标单次响应 | 内容层轻压，点击区域不动；焦点环保持清楚   |
| 次按钮       | 表面底、主文字、铅笔轮廓 | 淡色填充，轮廓加深     | 按下保持语义色，键盘显示焦点环             |
| 文字按钮     | 透明底、清晰文字         | 轻底色或下划线         | 聚焦仍有独立轮廓                           |
| 输入框       | 纸面底、可识别边界       | 边界稍加深             | 聚焦为强调色轮廓；错误为砖红并给出文字说明 |
| 导航项       | 紧凑、图标加文字         | 淡底色，图标播放一次   | 选中保留淡强调底和短标记，图标静止         |
| 可操作面板   | 清楚的可操作提示         | 改变底色或轮廓         | 焦点环；不通过位置变化表示可点击           |
| 普通内容面板 | 无外框，以留白组织       | 无额外交互             | 不生成无意义的焦点或悬停效果               |

主操作在同一区域保持一个明确的视觉优先项。危险操作使用错误色和明确文字，不仅依赖图标识别。错误信息靠近对应对象显示；成功反馈依据真实保存结果出现。

弹窗默认宽 480px，较宽内容 640px，最大宽度为视口减 32px；内边距 20px，操作间距 8px。浅色蒙层为 20% 墨色 `#20242B33`，深色蒙层约为 50% 黑色 `#00000080`；内容表面保持不透明。内容可纵向滚动，保留标题与操作可达，沿用 Ant Design 的焦点管理。浮层挂在明确的 Portal 上，基础浮层层级使用 1000；图形内部层级限制在画布自己的上下文。

## 7. 图形

处理节点初始宽度 248px，数据节点 288px，外部对象 264px；这些是类型级默认值，实际尺寸必须随内容测量，不按示例节点手调。内部留白 12px，内容区间隔 8px，分组留白 16px。

节点间距下限 24px，层间距下限 48px。布局算法可为节点、长路径、标签和跨边界关系增加空间，不把间距下限当作无条件排版结果。

- 节点名称和凝练业务说明直接显示，TS 结构及行内注释使用代码排版。
- 完整目录路径从 `modules/` 开始，目录标题单行呈现，测量时计入完整宽度。
- 连线使用当前模式的关系线色，说明 13px，端点多重性 12px；文字使用当前内容表面底衬和 4px 留白，减少线条干扰。
- 箭头、线型及多重性沿用既有图形语义，不因风格装饰改变。对象关联与请求返回等关系不混为同一种线。
- 不重新加入已移除的节点/连线 Hover 说明，也不默认加入节点展开或第三层导航。
- 项目综述中的图继续固定适应画布。业务设计图按既定规则支持平移和缩放，颜色、节点和线宽保持一致。
- 画布平移缩放由图形引擎单独控制，Motion 不再控制同一变换；批量图更新不逐个节点播放入场动画。

## 8. 动效

| 行为                 | 时长       | 表现                             |
| -------------------- | ---------- | -------------------------------- |
| 按下反馈             | 80ms       | 内容层最多缩到 0.99，释放复位    |
| 底色、轮廓和选中反馈 | 120ms      | 稳定位置的颜色或透明度变化       |
| 小范围显隐           | 160ms      | 淡入，最多 4px 位移              |
| 弹窗                 | 200ms      | 淡入，最多 6px 位移              |
| 抽屉                 | 220ms      | 从对应边缘进入                   |
| 动态图标             | 目标 480ms | 一次动作，按图标原始时长换算倍率 |

缓动使用无回弹的曲线，进入为 `[0.2, 0, 0, 1]`，退出为 `[0.4, 0, 1, 1]`。设计 Token 的时间统一用毫秒；Motion 适配层转成秒，AnimateIcons 的 duration 是倍率，不能直接传入毫秒。

常规交互优先使用 opacity/transform，不持续改变宽高、间距或阴影模糊半径。确有内容展开需求时单独验证布局成本。页面、列表和图节点默认没有滚动入场、连续抖动、自动弹跳或循环装饰动画。

`prefers-reduced-motion` 开启时，动态图标和装饰位移停止，状态即时切换；真实加载仍有文字反馈。MotionConfig 本身不替代所有自定义 SVG、CSS 和图标的减少动态处理，各适配层必须分别落实。

### AnimateIcons 放置评审

只使用 Lucide 系列，常规图标 16px，导航 18px，独立图标按钮 20px；固定宽高，图标动画不改变文字对齐或点击区域。

图标根容器使用 `ds-icon`：容器 inline-flex、行高为 0，内部 SVG 为 block，消除内联 SVG 的基线留白；不能依赖图标库输出的 Tailwind 类名生效。导航项使用 `ds-nav-item` 的双列网格，图标占固定 18px 列、文字占剩余列，两者居中；行高至少 36px，行间距 4px，触屏至少 44px。选中背景覆盖同一个导航行，不单独偏移图标或文字。标题、正文、目录从各自统一的内容边界对齐；概念名称和说明共享文字基线，避免用逐项位移修补。

| 位置                             | 是否动态     | 触发方式                                                |
| -------------------------------- | ------------ | ------------------------------------------------------- |
| 新建、保存、复制、重试等动作按钮 | 是           | 整个按钮 Hover 或键盘聚焦时播放一次；操作结果用真实反馈 |
| 项目综述、需求推进、业务设计导航 | 是，轻量     | 指针进入整行或键盘聚焦时一次；选中后静止                |
| 需要改变方向的折叠箭头           | 按状态变化   | 跟随展开/收起转向，由一个动画控制者负责                 |
| 品牌、正文旁的说明图标           | 静止         | 不自动播放                                              |
| 图节点类型、关系符号             | 静止         | 服务于识别，不干扰读图                                  |
| 成功、错误、提醒图标             | 通常静止     | 配合明确文字；确有需要的完成反馈最多一次                |
| 加载图标                         | 仅真实加载中 | 请求结束停止；减少动态时显示静态图标和加载文字          |

图标响应以按钮或导航行的整个命中范围为准，不能要求只 Hover 到图标本身。反复进入的重播间隔至少 600ms，同一控件一次播放；不对整个导航列表批量播放。触屏不模拟悬停，点击时以动作反馈为主。

图标由共同入口统一尺寸、颜色、播放和减少动态处理；按图标路径按需导入。图标本身通常 aria-hidden，控件提供可访问名称；纯图标按钮仍有明确名称及可通过聚焦获得的简短说明。

## 9. 可读性与性能验收

- 普通文字和代码在实际背景上对比度至少 4.5:1；有意义的控件边界、图标和图形线条至少 3:1。装饰分隔线与禁用元素单独处理，不把它们误当作正文或交互边界。
- 两种模式下已确认语义色的颜色配对由样板构建脚本计算，保留完整精度判定；该计算不能替代键盘、实际文字放大、读屏和完整页面验收。
- 键盘聚焦清晰，不被轮廓装饰或浮层裁切；目标尺寸和间距支持真实鼠标及触控操作。
- 稳定笔触在布局完成后呈现，尺寸提前确定；Hover 不重算图形布局。
- 动态图标只渲染实际需要的类型，在可见控件上响应操作，避免页面空闲时持续运行；字体本地加载，字标保持预留宽度。
- 样板中的静态节点仅验证视觉，不代表 ELK 布局、图形容量或真实业务已经通过测试。相应性能验收继续遵循图形调研及运行文档。

## 10. 代码结构和修改入口

```text
src/web/design-system/
├── tokens.json                  # 字体、排版、尺寸、形态、动效
├── themes.json                  # 明暗语义色和松针绿
├── tokens.ts                    # 类型化访问、CSS 变量转换和安装
├── appearance.ts                # 显示偏好的读取、保存和模式解析
├── AppearanceToggle.tsx         # 太阳／月亮按钮直接切换明暗主题
├── antd-theme.ts                # Ant Design 主题映射
├── DesignSystemProvider.tsx     # 运行时统一入口和明暗主题
├── global.css                   # 基础样式和共享阅读布局
└── fonts/                       # 英文字标及其 OFL
```

正式应用在 `src/web/main.tsx` 使用 Provider，样板在 `docs/ui/design-system-preview/main.jsx` 使用同一 Provider。初始背景脚本由 `scripts/design-theme-plugin.mjs` 从相同主题和偏好读取函数生成，开发与构建都有效，避免出现两套模式解析逻辑。

页面和业务组件读取语义变量或类型化 Token；尺寸、排版和颜色的调整从权威定义开始。阅读布局使用 `ds-reading-layout`、`ds-prose`、`ds-toc`。不包装全部 Ant Design 控件，不创建预留空目录，不让设计系统依赖业务。具体几何路径、布局算法输出和页面内容保持在各自职责中。

构建检查：`npm run design:build`；样板行为：`npm run test:design`；正式页面行为：`npm run test:e2e`。业务图尚未迁入，字体、布局和握手验证不能代替未来的图形性能验收。
