# 需求推进阅读

## 范围

页面读取数据库中已经保存的需求和推进记录。Agent 继续通过已有 MCP 工具保存；网页不新增另一套编辑、审批或自动回顾流程。不会用演示内容填充真实项目。

## 从列表到记录

左侧“需求推进”进入当前项目的需求列表。每行显示标题、当前状态、当前推进记录数和最近保存时间；支持名称筛选、六种现有状态筛选和分页。不增加负责人、优先级、百分比进度或不可逆终态。

需求是主阅读对象，推进记录只在所属需求内展示，不将不同需求的记录混排成全项目时间线。需求列表和详情均分别显示首次收录时间与最近更新时间；首次收录来自创建该需求身份的保存操作，最近更新来自当前需求修订。两者不代替需求在业务中实际提出的时间，历史提出日期没有材料时不推断。

需求列表按需求本身最近修订所处的项目版本倒序排列，同批更新用稳定身份消除排序歧义。点进需求后先展示当前正文、状态及真实状态更新时间，再展示推进记录。

推进记录按首次收录的项目版本、同批收录次序倒序排列，最新收录在前。每条身份只出现一次，读取该项目版本下的当前描述。修订旧记录保留首次收录位置；补录更早发生的结论则是新收录项。真实发生时间单独标注，未知明确显示未知，不用保存时间代替。收录和发生时间不能合并成一个日期。

每项需求的时间线使用 Ant Design Timeline，日期、轴线及记录正文明确区分：桌面时间栏位于轴线左侧、正文位于右侧，手机将时间置于记录标题上方。时间栏分别标注实际发生时间和收录时间，未知日期直接说明，保留完整结论。修订不在主时间线上产生另一条记录。

## 历史、状态依据和来源

需求的“修订与状态依据”和记录的“修订历史与来源”使用 Ant Design Drawer 按需阅读，不把每一版都重复塞进主时间线。修订按版本号倒序，展示该版标题、正文、保存时间、执行者、入口和必要说明。

需求正文修订且状态不变，不显示成一次状态变化；状态时间取最近一次真正状态变更。状态变化的依据固定到记录的具体修订，可打开当时的正文。后来的更正、归类变化或移除不替换旧依据。

原始来源按需读取，显示引用说明、原文、收录时间和定位信息。来源原文按纯文本呈现，不执行 HTML 或其中的指令。当前入口记录未认证的本机执行身份，不将 actorLabel 当作可信登录身份。

需求页和修订正文不展示综述关联、泛化关联说明或记录承接列表。主阅读保留需求说明和自身时间线，原始来源及状态依据仍从既有历史入口按需核对。界面精简不删除已经保存的历史及底层引用。

## 固定版本、分页和失败

列表首请求和需求详情在一致读事务取得项目版本。列表后续页、记录页、修订及来源读取显式携带该版本，不在翻页时悄悄混入新的写入。刷新会读取当前版本并开始新的分页；刷新失败保留上次取得的内容并明确提示，不能声称已同步。

需求列表按实际当前更新版本分页；记录按首次收录位置分页；修订按版本号分页。分页游标只定位当前项目与所读版本中的对象，不能从其他项目引用游标。当前已移除的需求返回不存在；历史读取允许移除修订。纠正记录归属后，当前时间线使用新的主需求，旧归属仍在历史中保留。

数据库是唯一权威，未增加表或迁移。读取仅查询本页所需需求、记录、修订和来源，不先导出完整项目、加载业务图或建立另一个内存权威副本。

## 实现和验证入口

- 内容结构：`src/contracts/content/requirements.ts`。
- HTTP 读取结构：`src/contracts/requirements-http.ts`，OpenAPI 从共享 Schema 生成。
- 读取与存储边界：`RequirementsReadService` 复用 `SnapshotRepository` 和原有来源读取。
- 页面：`src/web/requirements/`；路由为 `#/projects/<projectId>/requirements` 及其需求 ID 子路径。
- 接口验证：`tests/requirements-http.test.ts`，真实临时 SQLite 和 MCP 写入。
- 浏览器验证：`tests/e2e/requirements.spec.ts`，空状态、筛选、历史、来源、固定分页、刷新、项目隔离及窄屏。

以上不是超大需求库容量、跨平台或远程权限的验收结论。阶段回顾本身的专用列表和网页编辑仍待实现；业务设计阅读的实现边界见对应规范。
