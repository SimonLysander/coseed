# Agent 接入与使用指南

状态：**MCP、项目入口和综述阅读已接入，其他业务页面仍在开发**。本文是面向人的简版说明；Agent 的具体写作、引用和文件规范通过 `read_guide` 按需读取，后续继续校准提示词。

数据库保存权威内容及历史；Agent 直接连接 CoSeed 的 MCP 服务，读取完整当前资料，正式修改通过 MCP 提交。不使用资料 Git 仓库，不要求本地连接器或业务仓库提交 CoSeed 缓存。本机读写已通过官方 MCP 客户端测试；具体 Agent 产品的自动落盘及规范遵循仍需单独验证。

## 1. 连接 CoSeed

### 准备连接信息

取得 CoSeed 服务提供的 MCP 地址，以及实际需要的连接凭据。接入时确认 Agent 产品支持该服务采用的 MCP 连接方式。

当前开发实例的 MCP 默认地址是 `http://127.0.0.1:4310/mcp`，实际地址以启动输出为准；它仅用于同机连接。源码运行方法见[本地开发和运行](local-development.md)。远程部署及认证尚未实现。

### 在 Agent 中配置 MCP

通过 Agent 产品已有的 MCP 配置功能添加 CoSeed 服务。具体配置方式随客户端而定，后续根据实际验证补充示例。

### 确认连接成功

确认 MCP 初始化成功，工具列表包含 `read_guide`、`list_projects`、`get_project`、`export_snapshot`、`list_revisions`、`read_revision`、`get_operation`、`create_project`、`save_changes`。先读取 `read_guide(topic="usage")`；本机入口不代表已认证的人员身份。

## 2. 开始一个项目

### 选择或创建 CoSeed 项目

可以在页面选择、创建和切换项目；Agent 通过 `list_projects` 取得明确项目 ID，或用 `create_project` 创建空项目，版本为 0。项目标识由服务提供，不凭本地目录名称猜测。创建项目不强制登记业务仓库地址；用 `get_project` 取得当前资料版本。

### 拉取完整资料到本地

用 `export_snapshot` 固定已读项目版本，拉取综述、全部当前需求和推进记录、所有设计图及关联对象，还有实际引用的来源和必要历史。通过 `read_guide(topic="export")` 取得文件、分页和摘要规则。Agent 使用自身文件能力解码并保存到独立资料目录；没有文件能力的客户端可直接通过 MCP 读取，服务不会替远程客户端写文件。

分批拉取时固定同一项目内容版本，按服务清单检查文件和完整性；全部成功后才切换本地读取副本。下载失败不覆盖上一份完整副本。当前包不包含全部历次修订，额外历史可按需查询。

### 空项目：完成第一次梳理

已有资料的项目可继续下一节。空项目由 Agent 结合实际代码、已有文档和用户提供的背景，建立第一份项目资料，并保留可核对的来源；无法确认的历史讨论保持未知。

## 3. 推进一轮工作

### 结合现有资料理解任务

新任务或恢复会话时，先经 MCP 检查项目版本，过期则刷新本地副本。随后直接读取、搜索本地资料，结合用户当前目标和实际代码，明确本轮要解决的问题及影响范围。发现资料与代码不一致时，将差异纳入本次核对。

### 开发实现并验证结果

Agent 在业务项目中完成实现和必要验证，记录真实结果及受影响的设计。CoSeed 不负责执行 Agent，也不自动替用户提交业务代码。

### 发起阶段回顾

由用户明确发起回顾或资料同步，指定本次整理的讨论和代码范围。一次回顾可以涉及多个需求，不按每轮聊天或工具调用自动生成记录。

### 整理需求、推进记录和设计变化

维护受影响的需求及当前表述；新增真实结论或结果，修订误记的旧内容。同步检查相关节点、连线、数据结构和技术说明，有影响才修改，保持同一对象在不同图中的含义一致。

### 补齐本次修改的来源依据

为变化保留实际讨论、代码位置或验证结果，说明材料支持什么结论。实际发生时间未知时保留未知；资料所依据的业务代码状态与 CoSeed 数据版本分别记录。

## 4. 保存并查看结果

### 提交本次修改

用 `save_changes` 一次提交逻辑对象变化、原始依据、已读基准和本次 `requestKey`。已有对象沿用已读 ID 和修订；新对象和新来源使用本批 `$临时名称`，服务分配正式 ID 并返回映射。校验通过后，同一事务保存内容、修订、来源和操作结果，无强制准备步骤。本地缓存不是正式保存。

### 处理校验失败或版本冲突

校验失败时按实际错误修正内容；基准落后时刷新资料并重新核对，不能只改基准数字。保留尚未成功提交的修改。超时通过 `get_operation` 按原 `requestKey` 查询，或沿用原 key 和原始内容重试；同 key 不同内容拒绝。HTTP 请求上限为 1 MiB，超限整批不保存，当前不自动拆批。

### 确认保存并刷新本地副本

根据回执确认数据库已保存及对应项目版本。随后拉取完整最新快照并刷新本地副本；若期间有其他保存，最新版本可以高于本次回执，不能改写原回执。数据库已保存而下载失败时，只补做下载，不重复提交；旧副本保留它的真实版本。

### 查看修改内容及其依据

通过 `list_revisions` 和 `read_revision` 查看修订、来源及固定版本的历史图。Agent 简要说明实际保存内容、对应代码状态及未完成部分。项目综述已可在页面读取和刷新，需求推进及业务设计页面仍待接入。
