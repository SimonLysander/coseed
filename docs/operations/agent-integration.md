# Agent 接入与使用指南

状态：**简版内容草稿**。先确定从接入到查看结果的阅读顺序，后续按提示词标准细化 Agent 的行为、工具用法和内容要求。

目标架构已确认：数据库保存权威内容及历史；Agent 直接连接 CoSeed 的 MCP 服务，初始化拉取完整当前资料到本地，正式修改通过 MCP 提交。不使用资料 Git 仓库，不要求本地连接器或业务仓库提交 CoSeed 缓存。当前仅实现本机 MCP 握手和 ping，以下业务流程尚未接入，工具名称、参数和远程配置暂不编写为可执行示例。

## 1. 连接 CoSeed

### 准备连接信息

取得 CoSeed 服务提供的 MCP 地址，以及实际需要的连接凭据。接入时确认 Agent 产品支持该服务采用的 MCP 连接方式。

当前开发实例的 MCP 默认地址是 `http://127.0.0.1:4310/mcp`，实际地址以启动输出为准；它仅用于同机连接。源码运行方法见[本地开发和运行](local-development.md)。远程部署及认证尚未实现。

### 在 Agent 中配置 MCP

通过 Agent 产品已有的 MCP 配置功能添加 CoSeed 服务。具体配置方式随客户端而定，后续根据实际验证补充示例。

### 确认连接成功

确认 MCP 初始化成功，并能取得服务实际提供的能力。当前握手成功只说明连接成立，不代表项目读取和修改工具已经可用。

## 2. 开始一个项目

### 选择或创建 CoSeed 项目

选择明确的目标项目；尚未建立时先创建。项目标识由服务提供，Agent 不凭本地目录名称猜测。创建项目不强制登记业务仓库地址。

### 拉取完整资料到本地

经 MCP 拉取项目综述、全部需求和推进记录、所有设计图及关联对象，还有这些内容实际引用的来源。Agent 使用自身文件能力保存到独立资料目录；没有本地文件能力的客户端可直接通过 MCP 读取。

分批拉取时固定同一项目内容版本，按服务清单检查文件和完整性；全部成功后才切换本地读取副本。下载失败不覆盖上一份完整副本。当前包不包含全部历次修订，额外历史可按需查询。

### 空项目：完成第一次梳理

已有资料的项目可继续下一节。空项目由 Agent 结合实际代码、已有文档和用户提供的背景，建立第一份项目资料，并保留可核对的来源；无法确认的历史讨论保持未知。

## 3. 推进一轮工作

### 结合现有资料理解任务

新任务或恢复会话时，先经 MCP 检查项目版本，过期则刷新本地副本。随后直接读取、搜索本地资料，结合用户当前目标和实际代码，明确本轮要解决的问题及影响范围。发现资料与代码不一致时，将差异纳入本次核对。

### 开发实现并验证结果

Agent 在业务项目中完成实现和必要验证，记录真实结果及受影响的设计。CoSeed 不负责执行 Agent，也不自动替用户提交业务代码。

### 发起阶段回顾

由用户明确发起回顾或资料同步，指定本次整理的讨论和代码范围。一次回顾可以涉及多个需求，不按每轮聊天或工具调用自动生成记录。

### 整理需求、推进记录和设计变化

维护受影响的需求及当前表述；新增真实结论或结果，修订误记的旧内容。同步检查相关节点、连线、数据结构和技术说明，有影响才修改，保持同一对象在不同图中的含义一致。

### 补齐本次修改的来源依据

为变化保留实际讨论、代码位置或验证结果，说明材料支持什么结论。实际发生时间未知时保留未知；资料所依据的业务代码状态与 CoSeed 数据版本分别记录。

## 4. 保存并查看结果

### 提交本次修改

通过 MCP 提交本次逻辑对象变化、原始依据、读取资料时的基准项目版本及本次操作标识。服务校验后，在一个数据库事务中保存内容、修订、来源和操作结果。不要把修改本地缓存或上传整个目录当成正式保存。

### 处理校验失败或版本冲突

校验失败时按实际错误修正内容；基准已落后时，先刷新资料并重新核对，不能只改基准数字。保留尚未成功提交的修改。提交超时时按原操作标识查询结果，或沿用同一标识及相同内容重试，避免重复记录。具体工具调用及重试协议后续定稿。

### 确认保存并刷新本地副本

根据服务回执确认数据库已经保存及对应项目版本；页面重新查询即可读取。随后拉取完整最新快照并刷新本地副本。如果数据库已保存而本地刷新失败，只补做刷新，不重复提交内容；旧副本继续标记它的真实版本。

### 查看修改内容及其依据

在页面核对本次更新的需求、记录和设计，并查看相应来源及修订历史。Agent 简要说明已保存内容、对应代码状态，以及仍未完成的部分。
