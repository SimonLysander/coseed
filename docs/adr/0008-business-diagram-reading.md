# ADR 0008：业务图按版本投影，ELK 布局，X6 阅读

状态：已实施。2026-11-10。

## 问题

已有业务设计数据库及 MCP 保存模型，需要接入全景与模块内部阅读。内容必须与所读项目版本一致，目录归属不能与技术说明的范围混淆；交叉说明不能误圈无关对象。

## 决策

增加只读业务图 HTTP 投影，复用 SnapshotRepository 在同一事务解析成员及必要 owner。响应带固定项目版本、核心实现路径和明确图导航，不将数据库修订直接序列化为 X6 状态。共享节点更新无需复制图修订。

延续选定的 X6 + React Portal + ELK，不另引入图引擎。按实际 DOM 测量，ELK 负责 compound 布局、标签和正交路径，X6 只呈现路径及阅读交互。明确 JSON edgeCoords=PARENT，标签提供 text，避免跨层坐标与标签丢失。以几何检查筛选布局候选，失败直接报告。

目录是唯一父层次，技术说明是独立成员集合。用户明确选择支持交叉范围；原型拒绝交叉的限制废止。用成熟 polygon-clipping 0.15.7（MIT）计算成员矩形并集、排除无关对象，允许分离轮廓；编号建立说明与成员的对应。说明卡片用 ELK commentBox，不把技术范围强塞为 compound 父级。

## 影响

不修改核心数据模型或迁移，不绑定 Agent 客户端。全局设计系统增加说明和事件配色、图阅读尺寸；根 body 样式限制为文档根，避免污染 XHTML React 卡片。Web Worker 生命周期由共同 lease 管理。

密集图的标签会增加面积。默认保持可读比例并提供全图适应，不能以缩成不可读文字宣称解决大图阅读。当前没有浏览器 P50/P95 或容量 SLA；后续应以相同完整字段及标签建立基线，不能删信息换分数。

## 验证

真实 MCP 保存至临时 SQLite 后经 HTTP 和生产构建浏览器验证。语义文本、交叉成员排除、稳定目录、打乱输入顺序后的布局、版本一致性及隔离由测试覆盖。几何正确仍不等同于业务分析正确。
