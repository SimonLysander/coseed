# ADR 0005：MCP 直接保存，临时引用和操作标记由不同字段承担

状态：已实施。用户确认不设置强制准备／提交步骤，工具使用一次 `save_changes`，并保留独立的空项目创建。

## 决定

调用者按当前任务为一次逻辑保存选择稳定 `requestKey`；服务以动作、项目和 key 生成操作 ID。新对象与新来源使用本批 `$临时名称`，服务从操作身份、类型和名称生成正式 ID，解析明确的引用字段。已有对象必须使用实际读到的 ID 与修订。

所有正式保存继续通过共同服务，一次事务提交，并以规范请求摘要检查幂等。相同 key 同内容返回旧回执，不同内容拒绝；重启后行为不变。创建使用实例范围 key，保存使用项目范围 key。key 是重试关联，不是权限或用户身份。

不引入草稿表、保存票据、强制预检调用、自动合并或内容 Git。超过当前 HTTP 请求上限时整批拒绝，不悄悄拆开存在依赖的修改。

## 原因

原先的准备／提交提案用一份暂存草稿同时解决预览、ID 分配和重试，但引入额外调用、过期及草稿持久化，也把正常保存变复杂。ID 分配可以通过本批引用完成；重试则通过稳定意图标记和共同服务已经具备的幂等事务解决，不需要为了系统元数据增加一道用户流程。

## 代价和边界

调用者必须为一次保存保留相同 key 和原始请求，不能在超时后换 key 重复新增；不同逻辑保存需要不同 key。正式 ID 的生成规则在协议 v1 内保持稳定。仅重命名临时引用也算请求变化，不能用已成功的 key 改写请求。

当前没有远程认证，服务只绑定回环地址；执行者明确标为未认证的本机 MCP Agent。后续认证必须由可信连接上下文提供，不能把显示名或 requestKey 当作认证凭据。

数据仍由数据库管理版本。导出文件协议是可重建的读取视图，使用固定项目版本、规范 JSON 和摘要；格式版本不等于项目内容版本。详细契约见 [MCP 工具规范](../requirements/mcp-tools-design.md)，输入结构和内容约束以共享 Schema 为准。
