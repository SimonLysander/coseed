# ADR 0004：成功保存承载项目版本，图按项目快照解析

状态：**已实施于正式迁移、内容 Schema、共同保存／查询和 MCP 工具；业务页面接入待完成。** 本决策细化 ADR 0003，并替代上一版独立 project_versions 登记表和图内固定成员修订的设计。

## 决定

1. 一次成功保存对应一个项目内容版本，直接存入 write_operations；删除独立 project_versions 表。项目当前版本指向同项目的成功操作版本。
2. 图的范围和成员只存稳定 ID。查询时明确项目版本，图自身、节点、关系、技术说明及归属上下文都按这一版本选取当时最后有效修订。
3. 当前图使用当前项目版本；历史图必须指定历史项目版本。图自身的修订号不能单独标识完整图内容，因为共享节点变化不要求修改图清单。
4. 状态依据、记录承接等确实需要固定“当时哪一版”的业务关系，继续使用具体对象修订；不把历史证据改成跟随当前内容。

## 原因

独立登记表与成功保存严格一一对应，没有额外业务职责，却引入相互引用和额外封存步骤。成功操作本身足以作为项目版本锚点。

图清单固定节点修订会使“节点已经更新，但当前图仍显示旧内容”成为默认行为，还要求为传播变化复制图版本。统一项目快照既能更新当前视图，也能复原历史中的节点、归属名称和说明，不再保存 owner_revision_no 等额外版本指针。

## 保存及约束

服务预先确定操作 ID，在同一写事务中先写新修订、来源、关联并校验完整候选快照，最后插入成功操作行，再推进项目当前版本。子表对操作的外键采用延迟检查，提交前必须存在对应操作。

成功操作行存在即表示它的内容集合已封存。各修订及关联表禁止修改删除，也禁止给已存在的操作或父修订补插内容。没有成功操作的新修订无法通过事务提交。

共享节点、关系或说明变化时必须校验所有受影响的当前图；不能只校验本次直接编辑的图。第一版临时验证采用完整候选快照，后续增量优化必须保留这个语义。
