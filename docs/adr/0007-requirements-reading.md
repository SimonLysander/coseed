# ADR 0007：固定版本的需求阅读视图

状态：已采用。

## 问题

需求、记录、状态依据和来源已有完整保存模型。直接导出整个项目给页面会顺带加载业务图和全部材料；只分别读取各对象的“最新值”，又会在翻页或看旧依据时拼出不存在的历史。

需求更新时间、记录收录时间、实际发生时间和每版保存时间有不同含义，不能用一个“最新时间”替代。

## 决定

在现有项目内容模块内增加专门的需求读取服务，复用同一数据库和 SnapshotRepository，不复制保存规则。HTTP 控制器只做契约校验及投影。HTTP 复用已有项目入口的错误映射；与 MCP 共享存储和项目隔离边界。

首请求返回一致的项目版本；后续记录、历史和来源请求必须显式提供该版本。列表元数据、当前记录和历史分别分页，原文按需读取。当前页面不读取整张业务图，不使用全项目快照作为列表接口。

需求主时间线按创建时间倒序，同一时间以稳定身份排序，后续更新不移动主节点；需求内的推进记录以首次收录的版本与同批次序倒序，修订不移动原位置。实际发生时间独立显示。历史按修订号倒序，不把修订数量当作进展数量。

前端沿用 React Router、TanStack Query、Ant Design Timeline/Drawer/Collapse 和既有 Markdown。版本、项目和对象身份进入查询键；修订面板保存打开时的项目版本，页面刷新不替换已打开的历史依据。全局主题、布局、字体、圆角和动效继续取自设计系统。

## 影响和边界

无需新库表或迁移。所有需求状态与状态依据继续服从现有保存校验，不新增完成推断、审批或执行器状态。

页面主时间线以阅读为主；逐版信息进入按需展开的修订阅读。由于现有概念图和示例图只提供当前视图，历史综述和业务图暂不伪装为已实现的跳转。

分页限制读取结果大小；数据库仍需计算所读版本下的当前需求及记录，尚未据此承诺超大项目的延迟或吞吐。后续优化必须保留相同的固定版本与历史语义。
