# ADR 0003：数据库保存资料，Agent 拉取本地读取副本

状态：**数据库和 MCP 业务工具已实现；项目入口及综述已接入，Agent 宿主自动落盘和剩余业务页面仍待接入。** 2026-11-06，用户明确决定先不使用 Git 管理 CoSeed 资料。本文替代 [ADR 0002](0002-agent-workspace-sync.md) 的服务端 Git 存储方向；保留 Agent 使用自身 MCP 客户端直接连接 CoSeed 的决定。

## 决定

- 数据库保存项目资料、当前内容、不可变修订、原始来源及保存操作，是唯一权威存储。
- Agent 初始化项目时，经 MCP 拉取固定版本的完整当前资料，使用自身文件能力保存为本地读取副本；日常可直接读文件和搜索。
- Agent 的正式修改通过 MCP 提交；服务校验后在数据库事务中共同保存。网页编辑使用相同业务保存服务。
- 成功提交后刷新本地副本；开始新任务、恢复会话或提交前检查版本，过期时重新读取和核对。
- 第一版以项目内容版本检查冲突。版本由数据库维护，不使用 Git commit；对象修订号用于对象自身历史，二者通过同一次保存操作对应。
- 不要求独立连接器、Agent 本地运行 CoSeed 服务，或业务仓库提交 CoSeed 数据文件。客户端须具备 MCP 和本地文件能力；仅支持 MCP 的客户端仍可直接读取服务返回的内容，但不能宣称已有本地目录。

完整职责、目录草案、初始化、刷新、提交、失败恢复及验收边界以[存储及 Agent 读写流程](../database/storage-and-agent-flow.md)为准。

## 原因

当前需要的是完整读取、修订追溯、来源保存、冲突检测和历史恢复，这些能力可以由数据库及业务服务提供。没有已确定的需求要求用户直接 clone、编辑、分支或合并 CoSeed 资料。

Git 方案额外引入文件写入协议、跨文件校验、Git 保存后数据库索引与页面发布的一致性问题。Agent 需要本地文件，不意味着权威存储也必须是文件仓库；数据库内容可以导出为读取副本。

## 影响

1. 不开发资料 Git 仓库、commit/push 链路或 Git 到数据库的索引发布机制。CoSeed 源码和被描述业务代码仍可正常使用 Git。
2. 既有数据库内容和修订草案重新成为设计基础，但原有表数、SQL 及对象版本引用不自动成为正式迁移；仍需补齐项目快照、保存幂等及跨模块引用。
3. 本地目录是可重建缓存。目录损坏、删除或被编辑都不能改变数据库；上传不能直接把整个目录替换为权威内容。
4. “保存成功”指数据库事务已提交。本地副本更新失败不撤销已成功保存的内容，也不得因此重复新增记录。
5. 原始来源和历史修订仍须单独保存。把当前内容导出成文件并不能代替历史能力，也不能证明 Agent 已理解所有内容。

## 未覆盖

本次不确定最终 MCP 工具名、分页及上传协议、导出字段格式、快照保留时长、远程认证、共享节点的图版本传播或业务代码分支的资料视图。相关位置在流程文档中列出，实施前逐项收口。

现有实现仍仅有本机基础服务、数据库连接、MCP 握手和 ping，未新增项目读写、下载缓存或数据迁移。先前的 [Git 格式调研](../research/git-content-formats-2026.md)作为备选方案研究保留，不再是当前实施方向。

后续细化：[ADR 0004](0004-operation-snapshot-resolution.md)已确定成功操作承载项目版本，以及当前／历史图按项目快照解析，不再将共享节点的图版本传播列为未决项。其他未覆盖事项继续有效。
